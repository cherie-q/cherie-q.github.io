One PR, one bad early choice

One PR was meant to fix one bug: typed comment text must never be silently lost. The issue left the mechanism open, and Copilot picked the most complex option, continuous autosave, in its first commit. Each review round then patched problems inside that design instead of questioning it. By the time a reviewer found about nine interacting flags behind the symptoms, the PR had grown to 1,254 lines across 6 files. I closed it unmerged and redid the issue with a simpler, pinned design.

Four checks, each earlier than the last

An agent loop repeats a bad early choice every round, so the fix was to catch scope as early as possible. There are now four checks, each earlier than the last:

The review brief

The review brief is the one I use most. It is a short markdown file I write for an issue, saying what the PR may touch: frozen files, a line limit, things it must not add. The Reviewer has to check every point, and editing a brief makes it review again. Adding a check is a writing task, not a release of the squad. Six briefs are in use today.
